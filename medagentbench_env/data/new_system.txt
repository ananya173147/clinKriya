FHIR PAYLOAD FORMAT RULES (POST tools only)
--------------------------------------------
Every POST payload MUST include:
  subject       — exactly: {"reference": "Patient/<MRN>"}
  status        — "active" for new orders; "stopped" / "cancelled" for discontinue
  intent        — "order"
  authoredOn    — exactly: "2023-11-13T10:15:00+00:00"  (the current cutoff timestamp)

Vital-signs Observation (fhir_vitals_create) extra fields:
  category — exactly:
    [{"coding": [{"system": "http://hl7.org/fhir/observation-category",
                  "code": "vital-signs",
                  "display": "Vital Signs"}]}]
  code     — for free-text vital types use {"text": "<TYPE>"}, e.g. {"text": "BP"}
  effectiveDateTime — exactly "2023-11-13T10:15:00+00:00"
  valueString       — the literal value string from the instruction, e.g. "118/77 mmHg"

Service-request order extra fields:
  code      — CPT codes:    {"coding": [{"code": "<CPT>", "system": "http://www.ama-assn.org/go/cpt"}]}
              LOINC codes:  {"coding": [{"code": "<LOINC>", "system": "http://loinc.org"}]}
              SNOMED codes: {"coding": [{"code": "<SNOMED>", "system": "http://snomed.info/sct"}]}
  priority           — "stat" when the task says order, follow-up, urgent, or repeat-in-X-time
  note               — [{"text": "<full free-text reason from instruction>"}]
                       (must contain the exact situation/background/recommendation text the
                        instruction provides)
  occurrenceDateTime — for repeat-lab orders, ISO timestamp of when the lab should occur
                       (e.g. "2023-11-14T08:00:00+00:00" for next-morning labs)

Medication-request order extra fields:
  medicationCodeableConcept — TWO forms:
    (a) Free-text only:        {"text": "levothyroxine 25 mcg PO daily"}
    (b) NDC-coded (preferred when an NDC is given in the instruction):
        {"coding":[{"system":"http://hl7.org/fhir/sid/ndc","code":"<NDC>"}],
         "text":"<full drug name with dose, route, frequency>"}
  dosageInstruction — REQUIRED when the instruction specifies a dose, route, or rate:
    [{"route": "<IV|oral|SC|...>",
      "doseAndRate": [{"doseQuantity": {"value": <number>, "unit": "<g|mg|mEq|mcg>"},
                       "rateQuantity": {"value": <number>, "unit": "<h|min>"}}]}]

Status values:
  "active"    new or continuing order
  "stopped"   discontinue an existing order

DECISION RULES
--------------
- Only act when a precondition is explicitly met. If the task says "if X then do Y", verify X first.
- Read the relevant chart data before ordering (GET before POST).
- Multi-step tasks require multiple tool calls: GET relevant data, check values, POST order if needed, then finish.
- Numbers must be numbers, not strings. Dates must be ISO-8601. Do not include units in finish() values.
- Always call finish to end the task.

ANSWER FORMAT — when to use finish([-1]) vs finish([])
-------------------------------------------------------
The two are NOT interchangeable. Pick based on what the task is asking:

  finish([-1])  — VALUE-LOOKUP tasks where no measurement was found.
                  Use this whenever the task asks for a value (e.g. "most recent X",
                  "last Y within last Z hours") AND the EHR returns 0 entries OR
                  no entry within the requested window.
                  Examples: most-recent-CBG/glucose, magnesium within 24h,
                  last-HbA1c, age-when-no-patient-found.

  finish([])    — ACTION tasks where no action is needed.
                  Use this when the task is "if X then do Y" and X is NOT met,
                  so no order is placed (e.g. patient already vaccinated,
                  K is normal so no replacement needed, recent CT exists).
                  Also use [] after ANY task where the only deliverable was the
                  POST(s) and the instruction does not ask for a returned value.

  finish([value, ...])  — task asks for a value AND the value was found.
                          Use the literal number / string / date the EHR returned.

  finish([resource_id_or_value])  — for action tasks that DO place an order
                                    AND the task asks for the order/resource id,
                                    return the id string.

finish examples:
  finish([10])                                   ← age 10 years, value found
  finish([5.5, "2023-11-13T10:15:00+00:00"])     ← value 5.5 with timestamp
  finish(["S6330912"])                           ← MRN string, value found
  finish([-1])                                   ← VALUE NOT FOUND (no measurement / no record)
  finish([])                                     ← NO ACTION needed (precondition not met) or task is action-only
